Invoice Reminder
Serverless pipeline for invoice due dates

Event-driven ingestion · scheduled processing · automated reminders

AWS Solutions Architect / Data Engineer portfolio project

The problem

Tracking electronic invoice (Aruba XML) due dates by hand is tedious and error-prone. A missed deadline means a late payment and repetitive manual checking.

A concrete admin need, ideal for serverless automation.

The solution — what the pipeline does

An AWS system that ingests invoices and sends a reminder before the due date, with no servers.

1 · Ingest

The XML invoice lands in S3. The event wakes a Lambda that reads it.

→

2 · Store

Metadata (due date, amount, supplier) goes into DynamoDB.

→

3 · Check

EventBridge, on a schedule, wakes a Lambda that finds invoices nearing their due date.

→

4 · Notify

SES sends the reminder email before the due date.

Two decoupled triggers: event (ingestion) + schedule (reminder).

Architecture — event-driven in two phases

Phase 1 · Push

S3 receives the XML.
ObjectCreated event → parser Lambda → DynamoDB.

Work happens only when an invoice arrives.

→

State

DynamoDB holds the metadata.

It is the only contact point between the two phases: full decoupling.

→

Phase 2 · Pull

EventBridge schedule → reporter Lambda queries DynamoDB → SES sends the reminder.

Value and next steps

Why it matters (SA / DEA path)

  • Clean event-driven pattern: push + schedule decoupled.
  • Fully serverless, cost-conscious, IAM least privilege.
  • Aligned with the DEA-C01 certification.

Next steps (known limits)

  • Rewrite in IaC (AWS CDK Python): today it is console/CLI.
  • SQS + DLQ between S3 and Lambda for buffering and resilience.
  • CloudWatch alarms on Lambda errors.
  • Unit tests on XML parsing + Athena/QuickSight on the data.

Architectural honesty: the limits are stated and already have an evolution plan.
